1. CONFLITTI TRA FILE DUPLICATI
================================================================================

CONFLITTO #1 - CRITICO
File A: services/capeService.ts
File B: services/weatherService.ts (parametri hourly: cape, convective_inhibition, lifted_index)
Problema: capeService.ts fa una SECONDA richiesta separata a Open-Meteo per ottenere
CAPE, CIN e Lifted Index. weatherService.ts include già questi parametri nella
richiesta principale. Duplicazione di chiamate API.
Fix: Eliminare capeService.ts e usare i dati già presenti in weatherService.

CONFLITTO #2 - IMPORTANTE
File A: utils/termiche.ts
File B: services/termicheEngine.ts
Problema: Entrambi calcolano termiche (rateo, base, top, ecc.) ma con logiche
diverse. termicheEngine.ts usa CAPE reale da GFS + wind shear + ora del giorno.
termiche.ts è una versione più semplice. Vengono usati in componenti diversi.
Fix: Unificare in un unico servizio di calcolo termiche.

CONFLITTO #3 - IMPORTANTE
File A: utils/meteo.ts (trasformazione raw -> HourData)
File B: utils/transformMeteo.ts (trasformazione raw -> HourData/CurrentData/DailyData)
Problema: Due sistemi di trasformazione paralleli per gli stessi dati.
Fix: Usare solo transformMeteo.ts che è più completo.

CONFLITTO #4 - IMPORTANTE
File A: utils/algoritmoPrevisioni.ts
File B: services/termicheEngine.ts
Problema: Stessa logica implementata due volte: calcolo termiche multi-fonte con
climatologia + GFS.
Fix: Unificare in services/termicheEngine.ts.

CONFLITTO #5 - MEDIO
File A: components/MeteoController.tsx (fetch diretta a Open-Meteo)
File B: services/weatherService.ts (servizio ufficiale con cache)
Problema: MeteoController fa una richiesta completamente separata a Open-Meteo,
bypassando il sistema di cache e il servizio ufficiale.
Fix: MeteoController dovrebbe usare weatherService.fetchWeather().
